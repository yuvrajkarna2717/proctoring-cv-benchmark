# Testing guide

## Commands

```powershell
npm install
npm run fetch-models   # downloads the models once (63.2 MB), keeps each only if size and SHA-256 match
npm run fetch-models -- --check   # verify only; exit code 1 if missing or different
npm run dev            # http://localhost:5173 (COOP/COEP headers, no CSP)
npm run verify         # lint + format check + unit tests + production build
npm test               # unit tests only (Vitest, Node environment)
npm run smoke          # build, serve, and run the browser smoke test in installed Chrome
npm run smoke -- --channel=msedge --skip-build   # same test in installed Edge
npm run smoke -- --headed --seconds=15           # visible browser, 15 s measurement windows
npm run smoke -- --dev --seconds=3               # against the dev server (unbundled modules, no CSP)
```

`npm run preview` serves the production build (with CSP) at http://localhost:4173. Without the model file the face engine fails to initialize with an error that says to run `npm run fetch-models`, and the smoke test stops before starting a browser.

These tests were confirmed to fail when the logic they protect is removed: the scheduler rate test (naive interval rule gives 7.5 FPS instead of 7), the camera startup race tests, the Firefox frame-clock fallback tests, the stall tests (hidden-page gaps counted as stalls, focus state ignored, `document.hasFocus()` ignored), the controller's page-event logging test (monitor events not subscribed), and the measurement-window tests (monitor records frames dispatched before a reset; pipeline omits the dispatch time).

Phase 2 logic was checked the same way, with 18 small mutations (one or two lines each), each run against its test file; every one made at least one test fail: cooldown ignored or measured from the wrong time, gaps ignored, off-by-one confirm and clear boundaries, interrupted ends at the wrong frame, no hysteresis, other engines' results or disabled rules evaluated, `minFaces` boundary, every origin or every WebSocket host allowed, views of larger buffers transferred, non-monotonic timestamps, SHA-256 not checked, fallback ignoring `allowCpuFallback`, old task not closed on a delegate switch, violations evaluated after detection stopped. Two of them first survived and led to a stronger interrupt test and the new controller test. A nineteenth mutation hit code that could not change behaviour (the hidden-page flag was set twice); that code was removed.

Phase 3 logic: 24 mutations, all caught on the first run. YuNet scores not clamped, NMS boundary, RGB instead of BGR; alignment without the half-pixel correction or with the wrong rotation sign; the best-scored instead of the largest face embedded, detector coordinates not scaled to the frame, old sessions released under a running frame, fallback ignoring `allowWasmFallback`, model hash not checked; two faces passing the single-face check, negative roll or yaw unchecked, centre crops passing the face check; calibration comparing samples with their own capture, FRR counting scores equal to the threshold, genuine pairs decided by conditions instead of person; embeddings of another model compared, disagreeing samples enrolled, no sample spacing; FACE_MISMATCH at the threshold, rules fed the wrong input; the controller not ending a mismatch on a reference change or not passing similarity samples on; breakdown series not cleared on reset. Quantization follow-up: with the int8bq input pruning disabled, the engine test fails with `MODEL_SIGNATURE`, as the real model did.

Phase 6 logic: 39 mutations; 35 were caught on the first run.

- Decoders: NanoDet padding rounded instead of truncated, YOLOX scale by the larger ratio, BGR fed as RGB, anchor centre without the half-stride, softmax expectation not normalized, distances not multiplied by the stride, the score threshold ignored; YOLOX row and column swapped, sizes without `exp`, score without objectness; NMS ignoring classes, IoU equal to the threshold suppressed; letterbox offsets not undone (x or y).
- Filter and engines: classes not filtered, no maxDetections cap, the last instead of the best score per label; MediaPipe boxes divided by the wrong side or not clamped, no task recreation for a limit below 0.1, non-increasing timestamps, fallback ignoring `allowCpuFallback`; ONNX thread changes accepted live, the old session not released.
- Monitor: a score equal to the limit not counted, every engine's samples passed on, unbounded history.
- Rules: no gap reset of the vote window, a score equal to the limit not a hit, unbounded window, more votes than configured needed, no `source-changed` end, votes kept after an interrupt, the label limits not reported, no `maxScore`, votes above window accepted.
- Controller: object samples not passed to the rules, the source switched in the monitor only, non-object engines accepted as the source.

The 4 survivors (odd letterbox padding, horizontal padding of portrait frames, IoU exactly at the threshold, a score exactly at the rule limit) led to new assertions; then all 39 were caught.

Phase 6 follow-up (zoom pass): 18 mutations; 17 were caught on the first run. Tiles one size too small, no extra tile for too little overlap, a redundant tile for square frames, tiles placed edge to edge, crop offsets not added; merging across labels, without the containment test, or without the IoU test; MediaPipe crop boxes not mapped to the frame or normalized by the frame size, crops not closed, 320 px crops for Lite2, passes not merged; ONNX crops not closed, crops at 640 px, crop boxes not mapped or normalized by the frame size, the zoom option ignored. The survivor (merging without the IoU test) led to a test with two same-label boxes that overlap by IoU 0.6 while neither is 80% inside the other; then all 18 were caught.

Phase 5 logic: 18 mutations, all caught on the first run.

- Statistics: excluded rectangle counted, percentile off by one, no margin around the face box, sharpness divided by the standard deviation instead of the variance, downscale summing instead of averaging.
- Engine: stale face hints used, read not capped at `readWidth`.
- Assessment: backlit without a bright background, crushed shadows ignored, a dark frame without a face ignored, no face counted as lighting ok, face width ratio ignored.
- Rules: quality rules using the face rules' gap limit, old quality samples recorded on violations, reasons least frequent first, undecided samples not skipped.
- Controller: no face hint for image-quality engines, the first face used instead of the primary one.

Phase 4 logic: 28 mutations; 27 were caught on the first run.

- Measurements: yaw or roll sign flipped, matrix layout detection inverted, head correction of the iris offset reversed, the farther iris ring assigned to an eye, a closing eye not left out.
- Classification: no extra margin below the screen, no spatial hysteresis, closed eyes on the blink score alone, eye state decided with the head lowered, gaze decided with closed eyes, a baseline from the first frame instead of the median, a baseline used before `learnMs`.
- Calibration: extents not extrapolated to the edge, samples taken while settling, a moving gaze accepted, no movement to the edges accepted.
- Glances: counted in every direction, of any length, or never leaving the window (code removed with `GAZE_AWAY_REPEATED` on 2026-11-12).
- Rules: undecided samples ending a look away, escalation without waiting, the direction of the first frame instead of the largest measure.
- Controller and manager: any rule change making the preset custom, a baseline change not ending attention violations, every closure counted as a blink, frames evaluated during calibration.

The survivor, a calibration dropped at the start of a new detection session, led to a new assertion; then all 28 were caught.

The synthetic camera never shows a face, so I and J measure the detector-only path of the face engine (no landmark model). Latency with a real face comes from the manual checklist below.

Functional failures fail the run (exit code 1). Performance checks depend on machine load and are reported as WARN with the machine-wide CPU load measured during the same window. The JSON report (`reports/phase<N>-smoke-<channel>-<timestamp>.json`, phase 4 since Phase 4) contains every check, per-scenario latency summaries, per-frame face-result summaries, the request log summary, the device profile, and the lab's exported report.

These problems showed up in smoke runs and are now handled:

- In one Chrome run, frame callbacks stopped for the rest of the run while the video kept decoding frames. The cause was not isolated (the machine was heavily loaded). The frame clock watchdog now re-arms the callback and drives ticks from a timer during such stalls, and reports the stall.
- In one Edge run, the synthetic camera's track ended right after `getUserMedia`. The app now reports `TRACK_ENDED` instead of running on a dead stream; the smoke test retries camera start once and records each attempt.
- In one Chrome run after the real-webcam fixes, scenario E processed 5 of 16 frames because they reached the worker 0.85–0.99 ms after capture, under the 1 ms limit the scenario used (`reports/phase1-smoke-chrome-2026-11-10T05-58-39-799Z.json`). This was a flaw in the test, not in the app; scenario E now uses 0.01 ms.
- Runs after the average-FPS fix showed 5.11–5.13 FPS in some 8 s windows, with one more recorded outcome than dispatches: the result of a frame in flight at the metrics reset was recorded in the new window. The monitor now ignores such frames, and windows A and C check that recorded outcomes do not exceed dispatches.
- Edge's synthetic camera failed in two of five Edge runs on 2026-11-10: once its track ended during the memory measurement in window C (`reports/phase1-smoke-msedge-2026-11-10T06-02-29-032Z.json`), and once it ended at startup and the retry found no device (`reports/phase1-smoke-msedge-2026-11-10T06-20-37-038Z.json`). The app reported `TRACK_ENDED` both times. When the camera stops during a run, the smoke test now stops with the camera's error instead of failing every later scenario; rerun it.
- In the Phase 2 runs the synthetic camera failed twice more: Chrome's track ended during the memory measurement in window C (`reports/phase2-smoke-chrome-2026-11-10T09-16-57-404Z.json`, the first Chrome failure of this kind), and Edge's camera failed at startup again (`TRACK_ENDED`, then `DEVICE_NOT_FOUND` on the retry; `reports/phase2-smoke-msedge-2026-11-10T09-20-34-776Z.json`). Both passed when rerun.
- In the Phase 3 runs the synthetic camera ended its track in 4 of 8 runs: Edge twice (2.5 s and 1.4 s after camera start) and Chrome on the dev server twice (0.3 s and 33.3 s after camera start); every configuration passed when rerun. An eighth run failed on a bug in the new scenarios, since fixed. A bare `getUserMedia` page without any app code reproduced it in Edge: the track ended after 1.5 s, and the next `getUserMedia` call reported "Requested device not found". ## Manual webcam checklist (Phase 1 pipeline)

These steps use the diagnostic probes, which are off by default since Phase 2: turn on `probe-high` (and `probe-low` where noted) in their engine cards, and turn off the face engine for clean pipeline numbers.

Run `npm run dev`, open http://localhost:5173 in Chrome or Edge, and check:

1. Before consent, the camera cannot be started. After consent, Start camera prompts for permission and the preview shows the delivered resolution and frame rate.
2. Select another camera (if available); the device list shows labels after permission.
3. Start detection. `probe-high` reaches about 5 average FPS; the FRAME_PROBE mean luma drops when the lens is covered.
4. Set `probe-high` simulated work to 450 ms. Average FPS falls to about 2, skipped slots grow, and the preview stays smooth. Set it back to 0.
5. Enable `probe-low`. Both engines run; `probe-low` frames are 640 px wide.
6. Set fail-every-N to 5; failures are counted and shown, results continue. Set it back to 0.
7. Restart a worker; it returns to ready and the restart counter increments.
8. Measure memory (several seconds); totals per window and worker appear.
9. Export the report; the JSON contains configuration, device profile, and metrics, and no image data.
10. Stop the camera; the camera indicator light turns off and the event log shows every track ended.
11. Open the Environment page and confirm cross-origin isolation, WASM SIMD/threads, and WebGPU status.
12. While detection runs, switch to another tab for a few seconds and come back. The log shows "Page hidden" and "Page visible again"; "Page hidden / focus lost" counts it, and the event-loop lag cell reports hidden-page samples as excluded. Click another application window and back: "Window lost focus" and "Window regained focus" appear. A stall logged while the window was unfocused says "(window not focused)".

For numbers you want to compare, start detection, wait at least a minute without touching the page, then export the report.

Firefox (repeat steps 1–10 and 12) differs from Chromium in these expected ways:

- "Dropped / total video frames" shows "not reported by this browser", and the frame clock stays on `requestVideoFrameCallback`.
- "Missed frame callbacks" stays at 0 while the page is visible (0 of 4622 frames in a 163 s run). Each second the page is hidden adds about 27, because Firefox keeps presenting frames but runs the callback about once per second.
- After a tab switch (step 12), the log shows "Window lost focus" and "Page hidden", then "Window regained focus" and "Page visible again". In a run with two switches (18.5 s hidden), 21 event-loop samples were excluded, no stall was recorded, the frame clock counted 7 stalls, and the backup timer found 1 new frame, because Firefox still delivered about one frame per second.
- Long tasks show "not supported", and Measure memory reports that no API is available.
- The Environment page shows WebGPU available with empty adapter vendor and architecture.
- Capture time is higher than in Chrome (1.6 ms at 1280×720, 4.5 ms with the 640 px resize in the first session) while engine time is lower; see `docs/KNOWN_LIMITATIONS.md`.
